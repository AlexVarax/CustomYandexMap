# CustomYandexMap

**CustomYandexMap** — сервер на C++20 принимает JSON‑события с координатами и признаками сети, агрегирует их по сетке ячеек и отдаёт обновления клиенту по **WebSocket**; веб‑интерфейс на **API Яндекс.Карт** подсвечивает ячейки по доступности и показывает служебные метрики. Репозиторий рассчитан на нагрузочные эксперименты: есть **генератор нагрузки** (`loadgen`), интеграционный сценарий `build_test.sh` и скрипт быстрого демо `speed_demo.py`.

Цель — показать пользователям в каких районах сейчас доступен интернет и в какой степени.



## Об идее

Возникает проблема - блокировки интернета, и бывает трудно определить в каких районах они сейчас дейсвуют.

Здесь центр сценария зафиксирован в районе **Екатеринбурга** (широта/долгота около `56.8389`, `60.6057`), радиус проверки — до **1000 км**; фронтенд рисует сетку прямоугольников поверх Яндекс.Карты и перекрашивает их по проценту доступности, получая дельты с сервера.



## Архитектура

- **HTTP + WebSocket (Boost.Beast / Asio)**:
  - приём POST **`/ingest`** с телом JSON (`lat`, `lon`, `ts`, вложенный объект `flags`);
  - раздача статики из каталога **`frontend`** (главная страница с картой);
  - **`/ws`** — поток обновлений для браузера (дельты по ячейкам и вспомогательные метрики);
  - **`/metrics`** — текстовые метрики в стиле Prometheus для наблюдаемости.

- **Парсинг JSON** — **simdjson**; очередь между приёмом и агрегацией — **readerwriterqueue** (MPSC‑паттерн).

- **GeoValidator** — отбраковка точек вне радиуса от центра; счётчик `rejected_out_of_radius` доступен при остановке сервера.

- **Aggregator + CellGrid** — накопление выборок по ячейкам, скользящие окна по секундам, расчёт **availability** и формирование **дельт** для рассылки подписчикам WebSocket.

- **Опционально S2** — при установленной библиотеке **S2 Geometry** (`find_package(S2)`) включается `HAS_S2=1`; без неё проект собирается с `HAS_S2=0`.



## Функционал

- **Приём телеметрии** — HTTP POST на `/ingest` с JSON: координаты, время, набор булевых флагов (`wifi`, `mobile`, `whitelist`, `non_whitelist`, `vpn`, `yt_tg_no_vpn`, `geolocation`).
- **Фильтрация по расстоянию** — точки вне заданного радиуса от центра не учитываются; ведётся статистика отказов.
- **Агрегация по сетке** — распределение событий по ячейкам и расчёт показателей доступности для раскраски на карте.
- **Вещание в браузер** — WebSocket с пакетами `deltas` (идентификатор ячейки и `availability`) и блоком `metrics` (глубина очереди, доля потерь и т.д.).
- **Метрики для внешних систем** — эндпоинт `/metrics` для скрейпинга или ручной диагностики.
- **Нагрузочный генератор** — исполняемый файл `loadgen`: задаётся число сообщений и число потоков; отправка идёт на `/ingest` с сохранением соединения.
- **Контейнеризация** — многостадийный `Dockerfile` и `docker-compose.yml` с режимом через переменную `MODE` (`server` / `test` / прогон с большим числом сообщений).
- **Автотесты** — модульные тесты на Catch2 (парсер, геовалидация).

|------|------------|

| `src/parser/` | Разбор входящего JSON |
| `src/grid/` | Сетка ячеек и геопроверки |
| `src/aggregator/` | Очередь и фоновый цикл агрегации |
| `src/loadgen/` | Генератор нагрузки |
| `frontend/index.html` | Карта Яндекса, подписка на `/ws`, опрос `/metrics` |
| `tests/` | Catch2: `test_parser`, `test_geo` |
| `build_test.sh` | Сборка, unit‑тесты, подъём сервера, прогон `loadgen`, проверки `curl` |
| `speed_demo.py` | Локальное демо: при необходимости сборка, старт сервера, подача данных с заданным RPS, открытие UI в браузере |
| `Dockerfile`, `docker-compose.yml` | Сборка и запуск в Linux‑контейнере |



## Требования

| Компонент | Версия / примечание |
|-----------|----------------------|
| Компилятор C++ | **C++20** |
| CMake | **≥ 3.22** |
| Boost | **≥ 1.74** (компонент **system**, Beast через заголовки) |
| OpenSSL | заголовки и библиотеки для TLS/крипто зависимостей стека Beast |
| Потоки | **pthread** / аналог (через `Threads`) |
| Ninja (рекомендуется) | для сценариев в `Dockerfile` и `build_test.sh` |
| S2 Geometry | опционально, для расширенной геометрии |



**Docker:**

```bash
docker compose up --build
```

Порты по умолчанию: **8080** (HTTP/WS/статика), **9090** зарезервирован в compose (при необходимости используйте для дополнительного сервиса или прокси).

Переменная **`MODE`** в `docker-compose.yml`: `server` — только сервер; иные значения запускают сценарии с `loadgen` согласно `Dockerfile`.

## Демо и нагрузка

- **`speed_demo.py`** — удобный сценарий для Windows/Linux: при отсутствии бинарника выполнит конфигурацию и сборку, поднимет `monitor_server`, опционально откроет браузер и будет слать тестовые POST на `/ingest` с заданной скоростью и длительностью:

```bash
python speed_demo.py 60 300
```

(60 секунд, до 300 сообщений в секунду — параметры по умолчанию можно менять.)

- **`loadgen`** — максимально агрессивная генерация на C++:

```bash
./build/loadgen 1000000 4
```

(число сообщений и число потоков; см. `main` в `src/loadgen/generator.cpp`.)


## Типичные проблемы

- **Порт 8080 занят** — освободите порт или измените порт в коде `src/main.cpp` и пересоберите.
- **Firewall / антивирус** — для входящих POST и WebSocket с других машин может понадобиться правило для исполняемого файла `monitor_server`.
- **Boost / OpenSSL не найдены CMake** — задайте `CMAKE_PREFIX_PATH` или используйте менеджер пакетов (vcpkg, системные `-dev` пакеты в Linux).
- **Карта не отображается** — проверьте подключение к интернету и корректность ключа **API Яндекс.Карт** в `frontend/index.html` (при использовании ограничений по рефереру настройте их в кабинете разработчика Яндекса).
- **Высокая нагрузка и рост очереди** — смотрите `/metrics` и лог завершения сервера (`queue_depth`, `dropped`, `rejected_out_of_radius`); при необходимости уменьшайте интенсивность `loadgen` или масштабируйте инфраструктуру.
